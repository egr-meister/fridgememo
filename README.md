# FridgeMemo

Track food dates and organize your kitchen list. FridgeMemo is a simple, offline
home food inventory app built with React Native and Expo. Add food items, assign
them to storage categories, save purchase and expiration dates, see what should be
used soon, search by name, and keep a "Buy Again" list — all stored locally on your
device.

> FridgeMemo does not make medical, nutrition, allergy, diet, or food-safety claims.
> It is a simple note-keeping tool for food dates and kitchen stock.

## Features

- Add, edit, and delete food items
- Storage categories: Fridge, Freezer, Pantry, Spices, Drinks, Other
- Save purchase date and expiration date (simple `YYYY-MM-DD` text inputs)
- Automatic status: Fresh, Expiring Soon, Expired
- Home dashboard: total items, expiring soon, expired, buy-again count
- Search food by name (case-insensitive, partial match)
- "Buy Again" list with manual add, mark-as-bought, delete, and clear all
- Move a food item to the Buy Again list directly from the food list
- Configurable "Expiring Soon" window (1, 3, 5, or 7 days)
- Local reminder settings (on/off and a reminder time value)
- Clear-all-data option that restores defaults
- Works fully offline — no account, no cloud sync

## Run locally

```bash
npm install
npx expo start
```

Then press `a` to open on an Android emulator/device, or scan the QR code with the
Expo Go app. To build and run the native Android app directly:

```bash
npx expo run:android
```

## Build Android (release APK + AAB)

The native `android/` folder is generated by Expo on demand, so the build starts
with a prebuild step:

```bash
npm install
npx expo prebuild --platform android --no-install
cp proguard-rules.pro android/app/proguard-rules.pro
cd android
./gradlew assembleRelease   # produces a release APK
./gradlew bundleRelease     # produces a release AAB for Google Play
```

Output locations:

- APK: `android/app/build/outputs/apk/release/`
- AAB: `android/app/build/outputs/bundle/release/`

R8/ProGuard minification and resource shrinking are currently **disabled** in
`app.json` (`enableProguardInReleaseBuilds: false`,
`enableShrinkResourcesInReleaseBuilds: false`) to guarantee a stable release that
does not crash on launch. The ProGuard rules in `proguard-rules.pro` are kept in
the repo so minification can be re-enabled later (set both flags to `true`) and
tested on a device before shipping.

## Generate a signing keystore

Create a release keystore once and keep it private (never commit it):

```bash
keytool -genkeypair -v -keystore fridgememo-release-key.keystore \
  -alias fridgememo_key -keyalg RSA -keysize 2048 -validity 10000
```

You will be asked for a keystore password, a key password, and certificate details.
Remember these — you need the same keystore for every future Play Store update.

## Add GitHub Secrets

Convert the keystore to base64 so it can be stored as a secret:

```bash
# macOS / Linux
base64 -i fridgememo-release-key.keystore | tr -d '\n' > keystore.base64.txt

# Linux alternative
base64 -w 0 fridgememo-release-key.keystore > keystore.base64.txt
```

In your GitHub repository, go to **Settings → Secrets and variables → Actions →
New repository secret** and add:

| Secret name                 | Value                                            |
|-----------------------------|--------------------------------------------------|
| `ANDROID_KEYSTORE_BASE64`   | Contents of `keystore.base64.txt`                |
| `ANDROID_KEYSTORE_PASSWORD` | The keystore password                            |
| `ANDROID_KEY_ALIAS`         | The key alias (e.g. `fridgememo_key`)            |
| `ANDROID_KEY_PASSWORD`      | The key password                                 |

If these secrets are not set, the workflow still builds, but it falls back to the
debug keystore (not valid for Google Play upload).

## GitHub Actions build

The workflow at `.github/workflows/android-build.yml` runs on every push to `main`
(and can be triggered manually). It:

1. Checks out the repository
2. Installs Node.js 20 and JDK 17
3. Installs project dependencies
4. Installs **Android SDK Platform 35** and **Build Tools 35.0.0**
   (`sdkmanager "platforms;android-35" "build-tools;35.0.0"`)
5. Runs `expo prebuild` to generate the native Android project
6. Copies `proguard-rules.pro` into `android/app/`
7. Decodes the keystore from secrets and wires up release signing
8. Builds the release **APK** and **AAB**
9. Uploads both as build artifacts

Download the results from the workflow run's **Artifacts** section:

- `fridgememo-release.apk`
- `fridgememo-release.aab`

## Google Play compatibility

- Targets **Android API 35** (`targetSdkVersion 35`, `compileSdkVersion 35`)
- `minSdkVersion 24` (the minimum required by React Native 0.79)
- Built on a current Expo SDK / React Native version that supports API 35 and the
  **16 KB memory page sizes** required for Android 15+ devices, so the release AAB
  is suitable for Google Play upload
- No Firebase, ads, analytics, payment, or other external native SDKs

This configuration avoids the common Play Console rejections:

- "Your app currently targets API level 34 and must target at least API level 35"
- "Your app does not support 16 KB memory page sizes"

## Privacy

FridgeMemo does not collect, store, or share personal information. The app works
offline. Food items, dates, reminder settings, and app settings are stored only on
the user's device.

## App icon and splash screen

The app ships with custom branding (a simple fridge/food-note mark in soft green,
blue, and cream tones) — not the default Expo assets:

- `assets/icon.png` — app icon
- `assets/adaptive-icon.png` — Android adaptive icon foreground
- `assets/splash.png` — splash screen with the FridgeMemo name

These are configured in `app.json`. To replace them with your own artwork, swap the
PNG files (keep the same filenames and sizes) and rebuild. Recommended sizes:
icon and adaptive-icon `1024×1024`, splash around `1284×2778` (portrait).
